# Учебный стенд анализа процесса абсорбции

[Полное руководство пользователя](docs.md)

Настольное приложение для студентов АТПП, которое показывает причинно-следственную связь:

```text
возмущение → объект управления → изменение выхода → реакция регулятора
```

Программа использует общий материальный баланс газа и жидкости, условную степень извлечения η и динамическую модель первого порядка с запаздыванием. Она предназначена для учебных демонстраций; равновесие и кинетика массопередачи не рассчитываются.

Текущая версия: **1.5.4**. Датчик и механизм η, инструменты графиков и идентификация по CSV. [Отчёт о релизе 1.5.4](STATUS_1.5.4.md).

## Возможности

- два выхода общего процесса: концентрация обеднённого газа и концентрация насыщенного абсорбента;
- пять независимых входов: расходы газа и абсорбента в кг/ч, их концентрации и степень извлечения η;
- концентрации, η, задания и прогнозы в процентах; внутри расчёта и в CSV — доли; JSON-сеанс также сохраняет исходный текст полей;
- положительные и отрицательные возмущения состава и расхода в диапазоне от `−0,99` до `9,99`;
- ступенчатое, импульсное, временное прямоугольное и плавно нарастающее воздействие;
- настройка момента и длительности воздействия, времени моделирования, постоянной времени `T` и запаздывания `L`;
- сравнение исходного режима, отдельных возмущений состава и расхода и их совместного действия;
- сравнение свободной реакции объекта с P-, PI-, PD- и PID-регулированием через общую η;
- ограничение η, защита интегратора от насыщения и проверка достижимости задания;
- автоматический подбор параметров регулятора с учётом локальной чувствительности выхода к η;
- анализ чувствительности: семейства кривых для T, L, состава или расхода;
- учебная карта настроек P-, PI- и PID-регуляторов с категориями переходного процесса и переходом к выбранной точке;
- графики концентрации выхода, ошибки регулирования и фактической степени извлечения η;
- структурная схема, ход расчёта и показатели переходного процесса;
- готовые лабораторные сценарии с 30 воспроизводимыми вариантами каждого задания и режим предварительного прогноза результата;
- расширенные задания преподавателя: формулировка, методические указания, вопросы, число попыток, скрытые ответы и диапазоны настроек регулятора;
- пошаговый учебный маршрут и оценка направления, установившегося значения, скорости реакции, действия и настроек регулятора;
- режим преподавателя с созданием, копированием, проверкой полей, сортировкой и удалением пользовательских сценариев;
- импорт и экспорт комплектов сценариев в версионированном формате JSON;
- закрепление до шести опытов, наложение переходных процессов и сравнительная таблица;
- история опытов: переименование, возврат параметров в форму и сохранение/открытие учебного сеанса;
- экспорт объединённых результатов сравнения в CSV;
- адаптивные прокручиваемые панели и сворачиваемая навигация с иконками;
- интерактивные метки времени, полоса установления ±5% и отключение кривых через легенду;
- воспроизводимый шум датчика, фильтр D, инерция и предел скорости механизма η;
- общий курсор времени, активные инструменты и раздельные шкалы ошибки и управления;
- идентификация K, T и L по экспериментальному CSV с учебным примером и экспортом результата;
- MathText-оформление формул объекта, регуляторов и правил автоподбора;
- учебные подсказки для воздействий, параметров модели и показателей процесса;
- экспорт двух графиков в PNG, точек в CSV и протокола расчёта в TXT или буфер обмена;
- формирование самостоятельных HTML- и PDF-отчётов с параметрами, оценкой, выводом студента и встроенными графиками;
- экспорт HTML- и PDF-отчётов по всем закреплённым опытам.

Встроенные сценарии защищены от изменения и переработаны для общего баланса. Для каждого из семи сценариев доступны варианты с номерами от 1 до 30; вариант 1 сохраняет исходную конфигурацию, остальные детерминированно изменяют параметры расчёта. Пользовательские сценарии и настройки интерфейса сохраняются в `%APPDATA%\AbsorptionTrainer`. Запись выполняется атомарно, а предыдущая корректная версия сценариев хранится в резервной копии. Если основной файл повреждён, программа загружает резервную копию и предлагает восстановление. Сценарии и сеансы используют JSON версии 2; старые форматы отклоняются без миграции. Каждый опыт хранит параметры модели.

## Модель

Стационарные цели обеих фаз рассчитываются по общему переносу компонента:

```text
J = η · Gг · Xг
Gог = Gг − J
Gна = Gа + J
Xог = (Gг · Xг − J) / Gог
Xна = (Gа · Xа + J) / Gна
```

Базовые входы: `Gг = 1000`, `Gа = 7400` кг/ч, `Xг = 0.5`, `Xа = 97/370`, `η = 0.8`. Они дают `J = 400`, `Gог = 600`, `Gна = 7800` кг/ч, газовую концентрацию `1/6` (примерно 16,67%) и жидкостную `0.30` (30%). В интерфейсе входные концентрации и η задаются процентами.

При возмущении изменяются соответствующие входные параметры, затем пересчитывается общий баланс. При постоянной η изменение только расхода газа не меняет газовую стационарную концентрацию. Это свойство выбранной учебной модели.

Динамика каждого выхода задаётся звеном первого порядка:

```text
T · dy/dt + y = yуст(t − L)
```

По умолчанию `T = 10` с, `L = 2` с, горизонт опыта — 100 с. Стационарные цели удовлетворяют балансу; сглаженные переходные выходы не описывают накопление массы. Регулятор изменяет η в допустимом диапазоне с исходным смещением 80%; для газового и жидкостного выходов направление действия различается.

## Требования

- Python 3.14;
- Tkinter/ttk;
- NumPy;
- Matplotlib с поддержкой Tk.

В официальной сборке Python для Windows Tkinter обычно уже включён.

## Установка и запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

Если необходимые библиотеки уже установлены в выбранном интерпретаторе, достаточно выполнить:

```powershell
python main.py
```

## Проверка

Полный набор модульных тестов запускается командой:

```powershell
python -m unittest discover -s tests -v
```

## Сборка Windows-приложения

Установите зависимости сборки и запустите сценарий:

```powershell
python -m pip install -r requirements-dev.txt
.\build_windows.ps1
```

Проверенный результат создаётся по пути `dist\AbsorptionTrainer.exe`. В сборку включается встроенный комплект сценариев.

Версии прямых и транзитивных зависимостей закреплены в `requirements.txt` и `requirements-dev.txt`. Для воспроизводимой проверки используйте отдельное окружение Python 3.14.7 без системных пакетов. Сценарий сборки проверяет готовый EXE: запуск интерфейса, семь сценариев, идентификацию учебного CSV и восстановление лабораторной. Результат находится в `build\release-check.json`.

GitHub Actions проверяет `trunk` и запросы изменений на Windows и Linux. Linux использует виртуальный экран для тестов Tkinter. После успешных тестов Windows собирает и проверяет EXE, затем сохраняет приложение и руководство во вложении к запуску проверки.

## Сравнение опытов

После расчёта откройте «Результаты» и нажмите «Добавить текущий расчёт». Измените параметры, повторите расчёт и закрепите следующий опыт. На странице «Сравнение» можно:

- показать все или только выбранные переходные процессы;
- сравнить `T`, `L`, регулятор, максимальное отклонение, время установления и статическую ошибку;
- удалить отдельные опыты или очистить текущую выборку;
- экспортировать выбранные опыты в CSV и графики сравнения в PNG;
- переименовать опыт, вернуть его параметры в форму;
- сохранить историю в JSON и открыть её в следующем запуске программы.

## Ветки

- `stable` — стабильная версия и ветка по умолчанию;
- `trunk` — актуальная ветка разработки;
- `legacy` — предыдущая версия интерфейса на PySimpleGUI.
